# Plantbot 平台指南

> English version: [guide.en.md](guide.en.md)

Plantbot 是一个**多场站巡检机器人运营平台**：把不同品牌的巡检机器人和固定摄像头接进来，在一个控制台里看现场、派任务、管告警。机器人自己负责走路和避障；平台负责「今天巡哪里、谁去巡、发现了什么、证据在哪」。

界面默认浅色，已保存的明暗主题与语言选择会保留。手机底栏显示总览、视频、任务、机队；地图、事件、设备及管理模块位于“更多”。键盘可使用 Tab 切换控件、Enter 打开资源、Escape 关闭弹窗。

## 一、功能模块

打开控制台，左侧十个入口（其中 Integrations / Sites / Documentation 仅管理员可见）：

| 模块 | 它回答的问题 |
| --- | --- |
| **Overview 总览** | 现场现在什么样？——3D 厂区地图上看机器人在哪、哪里有告警，点一个航点就能派机器人过去 |
| **Live 视频** | 实时视频墙、按通道和时间检索录像、回放与下载；云台预置点、巡检计划和执行记录 |
| **Tasks 任务** | 任务模板与排程、周/月日历、执行归档、每点结果与关联事件，导出 CSV 或可打印报告 |
| **Fleet 机队** | 机器人们状态如何？——每台的电量、速度、在忙什么，配 3D 模型；「接入机器人」向导也在这里 |
| **Map 地图** | 厂区长什么样？——完整的作业地图：底图、区域、航点与机器人实时位置 |
| **Events 事件** | 告警看板与证据复核；缺陷台账记录等级、分类、提交人、责任人、处置历史和关闭说明 |
| **Assets 设备** | 被巡设备档案和卡片/表格视图；设备—位号—巡检点—数据类型—单位—地址台账 |
| **Integrations 集成**（管理员） | 外部系统怎么接？——托管连接器、API 密钥、事件词表、地图上传都在这一页 |
| **Sites 场站**（管理员） | 建站、画图（Site Builder）、管理用户、工厂/部门/岗位归属和登录/操作审计 |
| **Documentation 文档**（管理员） | 接口怎么用？——「API 与集成」参考：两份 OpenAPI 规范由运行中的平台在线渲染（永不漂移）+ 接入/嵌入指南 |

## 二、为什么「以场站为中心」

很多机器人管理软件是「以机器人为中心」的：路线存在机器人里、告警规则绑在机器人上。换一台机器人，一切重来。

Plantbot 反过来：**厂区的知识属于厂区，不属于某台机器人**。

- 巡检路线、地图、告警规则、摄像头，都挂在「场站」下面。
- 机器人只是执行者：今天 Spot 去巡这条线，明天换 X30 去巡同一条线，路线不用改。
- 一个平台管多个场站，每个场站有自己的一套东西，互不干扰。

交付一个新场站的顺序也因此很直白：**建站 → 传地图 → 摆航点画区域 → 接机器人**。前三步在 Site Builder 里点几下鼠标，最后一步见下一节。

## 三、机器人怎么接进来

两条路，按你的网络情况选：

### 路线 A：平台托管（推荐，适合平台和机器人在同一内网）

在 **Integrations → 托管连接器** 里点「新建」，选机器人品牌，填三样东西：机器人的 IP 地址、登录凭证、（可选）机身相机的 rtsp 视频地址（可多条）。点「创建并启动」——完事。

平台会替你运行对接程序：崩了自动重启，日志随时可看，平台重启后自动恢复。机器人几秒内出现在机队里，机身相机直接变成视频墙上的一路画面。

目前内置三种型号的对接程序：波士顿动力 Spot、云深处 X30、高新兴 GS Patrol F2——都按厂商官方协议实现。

### 路线 B：外置 adapter（适合跨网络，或内置三型号之外的机器人）

如果平台部署在云上、机器人在厂里（网络不通），或者你要接一台我们没内置的机器人，就自己跑一个小程序（叫 adapter）放在机器人旁边。它做四件事：注册机器人、每秒报一次位置电量、领任务、报告发现。

写这个小程序有现成的工具包，两种口味：

- **TypeScript**（`sdk/adapter-sdk-ts`）：约 50 行代码接一台机器人；
- **Node-RED**（`sdk/node-red-contrib-plantbot`）：不写代码，拖四个节点连成一个流程即可，工厂里常见的 Modbus/MQTT 设备也能顺手接进来。

不管哪条路，鉴权都是一把「场站密钥」（在 Integrations 页签发，明文只显示一次）。

### 机器人怎么出现在地图上

机器人接入后，会以它**真实上报的位置**出现在 Overview / Map 场景里。如果机器人用自己的建图坐标系导航（多数真机如此），先在 场站搭建器的标定页做一次标定（在地图上点两个以上对应点，平台自动算出换算关系），把结果填进连接器表单——之后机器人的位置就和厂区地图严丝合缝。

## 四、数据是开放的

平台的重要数据都能用同一把场站密钥经 HTTP 读走，方便对接报表、工单、大屏等第三方系统：

- 机队与实时状态（位置、电量、在忙什么）
- 事件流（可按时间、状态、类别过滤）
- 任务记录与排程
- 视频通道清单
- 传感器读数（按指标查时间段）

完整的接口定义是标准 **OpenAPI 3.0 文档**，共两份：集成面 [openapi.yaml](openapi.yaml)（机器人上报 + 只读数据），和覆盖控制台全部操作的会话面 [openapi-platform.yaml](openapi-platform.yaml)。运行中的平台都在线提供（`GET /api/integration/v1/openapi.json` 与 `GET /api/openapi.json`，无需鉴权）。把它们拖进任何 OpenAPI 工具（Swagger UI、Postman、Apifox）就能浏览和调试。

要把 Plantbot **嵌进你自己的系统**？页面支持 iframe 嵌入（`?embed=1&site=…`）：去掉品牌栏/工具区/侧栏，但**保留一条紧凑的模块导航条**，用户仍能在模块间切换（`?embed=0` 退出，按标签页会话粘滞）。用 `?embednav=top|bottom|hidden` 控制这条导航条的位置——`top`（默认，纤细顶条）、`bottom`（宿主已占用顶边时下移）、或 `hidden`（隐藏，由宿主自行经 URL 驱动导航）。登录支持对接你的统一身份（OIDC/OAuth2 单点登录）——细节见 [integration.md](integration.md) 的「嵌入与 SSO」一节。

含视频源地址（内嵌账号密码）的字段永远不会从这些接口流出——看视频走播放会话，取证据帧走快照接口。

## 五、巡检运营扩展

首次使用录像，在 Live → Recordings 由管理员按通道开启并设定 1–30 天保留；启用前的视频不会补录。云台先保存命名预置点，再排顺序和停留时长；只有支持绝对定位且回报到位的 adapter 才能执行。每周云台计划使用 UTC。现有 F2 仅支持复位，方向控制缺少可靠停止协议；Spot CAM 支持回读姿态、预置点与巡检；X30 robotserver 不提供云台定位。位置不确定时，操作员先确认摄像头停止，再解除占用。

设备与位号由管理员维护；位号可绑定已接入机器人的指标，协议和凭证仍在 adapter/connector 中。操作员在 Events → Defects 提交、指派和处理缺陷，关闭必须填写结果，重开保留原处置历史。组织目录只记录归属，场站角色仍单独管理；事件词表在 Integrations → Event types。云台巡视不会自动抓拍或调用 AI，外部算法继续通过事件/读数/证据接口接入。

## 视觉巡检

在 Live → 视觉巡检中查看 Adapter 视频源，添加 11 项预置监测之一，试运行获取画面后设置区域、计数线、阈值与 UTC 班次。启用后可查看原图、标注、读数和配置版本，异常进入事件记录。固定视角是连续规则的前提；移动相机 OCR 需要设备确认停稳。Server / Adapter 分包安装和现场配置见 [release.md](release.md) 与 [vision.md](vision.md)。
